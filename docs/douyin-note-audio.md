# 抖音图文配乐下载 404 修复（0.8.3）

## 问题与证据

手机 0.8.2 对分享链接 `https://v.douyin.com/NfbcEji8BSE/` 提取失败。
短链指向图文作品 `7605520822433968122`（`aweme_type=2`）。
诊断显示公开分享页取得目标作品，但音乐候选为 0、视频候选为 1，下载返回 HTTP 404。

实际返回的 `music` 只有曲名等信息，没有 `play_url`；
`video.play_addr.url_list` 是把一个 MP3 URL 填入 `video_id` 参数的播放包装入口。
真正配乐位于 `video.play_addr.uri`，直接请求已验证 HTTP 206、`audio/mpeg`。
原代码只读 `url_list`，漏读这个地址。该问题与 B 站 412 或服务器账号无关。

## 改动范围

- 新增纯解析函数 `douyinNoteAudioUrls`，仅处理已确认的 `aweme_type=2` 图文类型。
- 仅接受 HTTPS、443、无用户信息、`douyinstatic.com` 或其子域、`/obj/ies-music/*.mp3` 地址。
- 将有效图文配乐补入音乐候选，保留已有音乐地址优先级及去重。
- 普通视频与 B 站提取逻辑不变；无有效配乐时仍保留现有选择逻辑。
- 使用现有下载、音轨检测、临时文件校验及原子保存流程。MP3 不重新编码。
- 不新增服务器接口、凭据、数据库迁移或登录要求。

## 回归与边界

新增 4 项 JVM 测试：图文直接音乐、普通视频隔离、不安全/不支持的 URI、缺失字段。
修复前新测试因函数尚不存在编译失败；实现后全部 58 项 JVM 测试通过。
`testDebugUnitTest lintDebug assembleDebug assembleRelease --offline` 构建成功；Lint 无错误。

真机提取验收结果见下方交付记录。该分支只覆盖已验证的数据格式；不保证私密、删除、付费或其他格式作品可提取。
