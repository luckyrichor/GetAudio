# 0.6.1 提取与服务器授权修复

## 原因与处理

手机当前应用为 `com.getaudio.app`；此前保存服务器访问凭据的是 `com.getaudio.app.preview`。不同包名不共享私有目录，当前应用新安装后缺少 `files/server-access.json`。Nginx 日志显示手机提取请求没有认证用户名，返回 401。服务器健康接口 `/health` 公开可访问，原测试连接只检查它，因此不能说明提取接口已授权。

“我的 → 服务器设置”增加用户名及隐藏密码输入；默认用户名为 lck80，未预设密码。用户输入现有服务器凭据后，通过 HTTPS 请求受保护的 `/sync?limit=1` 验证。验证成功才原子替换私有配置并更新运行中客户端，失败保留原配置。密码输入框不回显已保存密码；配置已存在且用户名未改时，密码留空沿用原值。配置只允许应用用户读写，不打包进 APK、Git 或日志。访问凭据只发送至 tx 的 HTTPS 主机和端口，验证请求不跟随重定向；自定义服务器不会收到 tx 凭据。

这组服务器访问凭据与手机号账号、抖音/B站登录分开。服务器依旧由 Nginx 验证密码；本次不修改服务器密码或扩大公网权限。应用重装后的恢复由用户重新输入完成。

本地失败媒体下载成功，共 9,866,617 字节。手机 MediaExtractor 能读到 AAC 帧，但前两帧时间为 −46,439 和 −23,219 微秒，轨道声明 `encoder-delay=2048`。旧代码以首帧时间是否非负判断是否有数据，因此误报“音轨没有可读取的数据”。

修复用实际读帧结果判断是否为空。仅在负起始时间且声明编码延迟时 seek 到有效起点；不固定删除任何数量的帧。零/正起点不 seek；未声明预热的负时间帧全部保留，仅给时间戳加统一偏移，保证帧间时间间隔不变。本次没有改下载选路、重编码或自动转服务器的行为。

## 验证

- Android `testDebugUnitTest lintDebug assembleDebug` 成功：43 项单元测试通过，Lint 0 错误、23 警告。包括错误密码不能覆盖已保存凭据、重新打开保持配置、密码留空保持原值、缺失/损坏配置，以及零/正起点不裁帧、负时间不等于预热的回归。
- 同一 REDMI K80 上，以旧 APK 的真实抽轨方法处理失败媒体，重现异常；新 APK 方法处理同一文件成功，输出 M4A，919 个有效编码帧与原媒体逐帧 SHA-256 一致。
- 零起点 AAC 对照样本 921 帧全部保留，逐帧 SHA-256 一致。样本由原失败媒体无重编码重封装得到，不能视为覆盖所有 AAC 编码器。
- 手机原地升级到 0.6.1 / versionCode 15，沿用原包名及 tx 签名。真机提取原失败分享链接成功，保存 345,871 字节音频并加入本地库。
- 补齐已有剪辑模块使用 Media3 Transformer 所需的 `OptIn` 声明；没有改剪辑行为。

补充真机验收：

- 用户在新增设置页输入原密码并保存成功，私有配置权限核对为 600。
- 同一失败链接通过服务器提取、下载成功，Nginx 记录带 lck80 的 POST /extract 200、GET /audio/5 200，共 297,711 字节；本地及服务端采取各自已有选路，文件字节数可以不同。
- 重启应用后云端同步成功，授权仍生效。B站音频在手机处于 PLAYING 状态，进度正常推进；本地提取成品播放至约 21 秒正常结束，无播放器错误。
- 独立生成的 48 kHz 单声道零起点 AAC 共 48 帧，逐帧哈希一致；MP3 走原音频保留路径，返回 mp3。

声明编码延迟但 seek 后仍为负值或跳至非零时刻的特殊轨道，尚未完成样本验证。以上不代表所有平台、编码器或手机型号均已覆盖；平台反爬、特殊编码及不完整下载仍可能独立失败。
