# 当前播放列表拖拽排序（0.8.4）

## 用户操作

在底部正在播放栏打开播放列表，长按歌曲行或左侧拖动标识，上下拖动调整位置。
行序号随预览顺序更新，当前歌曲仍按音频 ID 高亮。
拖到可视区域顶部或底部时自动滚动，支持超过一屏的列表。
松手后保存；系统取消手势或实时队列变化时放弃尚未提交的拖动。
播放、暂停和移除仍由独立按钮触发，保存期间暂时禁用操作。
辅助功能提供“上移”“下移”操作。

## 数据与播放器

- `ReorderableQueue` 按稳定音频 ID 构建拖动预览，只在松手时提交一次。
- `queueReorderMoves` 验证目标是当前 ID 列表的完整排列；重复 ID、增减成员、已过期的快照均拒绝，不会复活已删除音频。
- `PlayerHolder.reorder` 通过队列互斥锁协调添加、移除、列表删除与重排；核对当前来源列表和 Media3 实际队列 ID。
- `PlaylistRepository.reorder` 在 Room 事务中重新验证成员，只更新 `playlist_items.orderIndex`，保留音频元数据、文件、加入时间和列表引用。
- 数据保存后用 `moveMediaItem` 移动现有 Media3 项，不重新设置音源或 seek，从而保留当前歌曲、播放进度、暂停/播放状态；更新当前索引。播放方式与定时设置不变。
- 写入开始后完成保存与播放器同步，避免关闭弹窗的协程取消打断提交。
- 保存后使用最新队列元数据重建顺序，避免期间重命名被旧标题覆盖。
- 仅修改当前播放列表。其他列表及音频库展示顺序不变。无数据库版本迁移或新增服务器接口。
