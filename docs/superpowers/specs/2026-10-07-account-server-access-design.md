# GetAudio：账号访问服务器与平台授权统一方案

状态：待审阅；本文件是设计，不是已实现功能。依据 GetAudio@ff26a70；2026-10-07 对本地代码及 tx Nginx 配置进行只读核对。

## 目标与范围

已注册用户以自己的 GetAudio 手机号＋密码登录后，使用个人会话令牌进行服务器提取、同步、下载、音频助手及平台授权，不再配置共享 Nginx 用户名/密码。抖音和 B站是同一 GetAudio 账号下可并存的平台授权；本次不实现以平台身份直接登录 GetAudio，不加入短信登录或忘记密码。

手机直提取和设备已下载的音频继续离线可用。平台授权不是每个公开链接的必需条件；只有平台要求时才提示授权。手机号仍未通过短信验证，页面明确其当前限制。

## 已核对现状

- tx API 监听 127.0.0.1:8800，Nginx 和 API 均运行。除 /health 外，现有 HTTPS 路径统一要求 Basic Auth。
- AppSession 已实现令牌哈希、30 天有效期、退出撤销；Android 加密保存令牌，并仅向绑定源发送 X-GetAudio-Session。
- PlatformCredential 以 (user_id, platform) 唯一，两个平台可以同时挂到同一已登录账号。
- 访客凭证归属设备 UUID，登录后尚未迁移；UUID 本身不构成可靠的归属验证。
- tracks 的唯一约束是全局 (platform, video_id)。/tracks、/sync、/audio 及模型曲目候选仍读取共享库。pipeline 查重可跳过平台访问验证，force 会覆盖全局记录。
- 手机正编号记录、同步游标及删除抑制尚未按服务器账号分区。

## 选择的方案

采用新增账号专用 API 加逐步迁移。直接去掉全站 Basic 会暴露旧访客接口；只修改页面而继续内置共享密码则没有解决问题。新增 /v2 账号接口，使新手机不依赖 Basic；旧接口保留 Basic 管理入口，避免旧包突然损坏，并阻止旧访客绕过账号认证。

Nginx 仅放行明确的账号注册/登录/状态/退出、账号专用 /v2 路由与已有认证的 Agent v2 路由，其余旧路径继续 Basic。API 必须自身执行鉴权，不能信任 Nginx 转发的任意用户 ID。8800 保持回环监听。

## 用户流程与页面

1. 用户点击服务器提取或云端同步；未登录显示“请先登录 GetAudio 账号”，提供进入账号页面的入口，不引导填写服务器密码。
2. 手机号账号注册/登录成功后，所有个人服务器操作携带会话令牌，服务器从令牌推导账号。
3. 我的页面将“抖音 / B站平台登录”改为“平台授权”。页面显示当前账号及两张独立平台状态卡，分别提供授权、重新授权和解除授权；游客先登录 GetAudio。
4. 服务器设置保留默认 tx 地址、地址修改和连接检查；移除普通用户可见的服务器用户名/密码。健康检查只表示连通；账号状态另行验证，明确区分未登录、过期和网络故障。
5. 切换账号时清空内存会话状态、暂停当前账号云端播放并切换云端库分区；设备本地提取音频及用户播放列表文件不被删除。原账号云端缓存隐藏且保留，可在重新登录时恢复。
6. 不把抖音/B站授权写成 GetAudio 登录，也不按昵称、手机号猜测合并平台身份。

## 身份与 API 合约

沿用 HTTPS 及 X-GetAudio-Session，不在 APK 内置 Basic 密码，不将凭据记录到日志或文档。注册/登录仍只发送手机号和 GetAudio 密码；服务端保留现有限流并核对代理真实 IP 处理。

| 方法/路径 | 输入及约束 | 输出/行为 |
|---|---|---|
| POST /account/register、/account/login | 沿用 phone、password；不需 Basic | 账号及会话令牌；错误保持 400/401/409/422/429 |
| GET /account/me；POST /account/logout | 个人会话令牌 | 当前身份；撤销当前会话 |
| POST /v2/extract | text 必填；force 可选；不接受客户端 user_id | 当前账号曲目与 reused；提取使用该账号平台凭证 |
| GET /v2/tracks | q/platform 可选；limit 1–200；offset 非负 | 仅当前账号有效曲目 |
| GET /v2/sync | cursor 非负；limit 1–500 | 当前账号增量与 tombstone；next_cursor/has_more |
| GET /v2/audio/{id} | 曲目 ID，需个人令牌 | 有权曲目的音频，支持现有流式下载；越权与不存在统一 404 |
| GET /v2/platforms | 个人令牌 | 可用授权方式；平台支持范围不变 |
| POST /v2/platforms/{platform}/qr | platform 仅 douyin/bilibili | 当前账号拥有的 session_id、到期时间、二维码路径 |
| GET /v2/platforms/qr/{sid}、/image | QR 会话必须属于当前账号 | 状态或图片；越权 404；过期不可复用 |
| POST /v2/platforms/{platform}/cookies | cookies 必填，限制长度，字段不回显 | 加密保存到当前账号；沿用平台校验 |
| GET /v2/platforms/credentials | 个人令牌 | 平台及有效状态，无 Cookie 正文 |
| DELETE /v2/platforms/{platform} | 个人令牌 | 仅解除自己的平台授权 |
| POST /v2/migration/claim | 一次性迁移票据，个人令牌 | 原子迁移明确归属的访客凭证；不接受裸 UUID 认领 |

其他关键错误：401 未登录/令牌失效，404 资源不可见，409 迁移冲突或重复状态，429 频率限制，502 平台提取失败。平台要求授权应有独立业务错误码，避免混淆账号过期。二维码图片请求也携带同源会话令牌，跨源重定向不得泄露令牌。

## 音频归属、去重与数据迁移

采用按账号分区的 Track：增加 owner_scope，历史值为 legacy；唯一约束调整为 (owner_scope, platform, video_id)，索引和查询同时包含账号。对 SQLite 采用明确版本迁移，在事务内重建约束、复制全部旧列/ID及引用，核验行数、外键和完整性；不能用 create_all 假装更新旧约束。

正编号沿用全库唯一 ID，旧编号不改、不碰设备本地负编号。新音频产物和提取临时目录也按账号隔离；同账号查重可复用自己的成功产物，跨账号不能直接返回缓存或使用他人 Cookie。force 只能覆盖当前账号的记录/文件；同账号同链接并发有锁，不同账号不共享可变输出路径。

任务用户 ID 来自已验证会话。同步、下载、二维码状态、凭证、助手曲目候选及成功证据校验均过滤账号。旧 Agent/访客路径继续管理入口保护；新 Agent 不读取 legacy 或其他账号曲目。

历史共享音频不批量发给每个注册用户。可依据成功 ExtractJob 的可信归属迁移到对应账号；多账号共享同曲目时复制独立记录及文件引用，避免后续 force 互相覆盖。没有归属证据的音频保留 legacy，不删除、不自动认领。手机已有下载文件保留，迁移时仅匹配已验证的记录；不得根据标题猜测所有权。

Android 为云端记录增加服务器源/账号归属，同步游标与删除抑制按该分区保存。旧库升级保留全部音频和播放列表引用；能确认当前账号归属的记录迁移到该账号，无法确认的保留设备历史分区，不自动上传或供其他账号同步。网络操作开始固定账号快照，完成入库前再次检查身份，阻止切换账号后的晚到结果写入新账号分区。

## 访客平台凭证迁移

新平台授权先要求登录；已有账号凭证无需迁移。旧访客凭证必须证明来源设备归属，不能提交任意 guest UUID 即认领。

为当前受控开发手机，可在用户授权调试范围内只读核对应用私有访客标识，由服务端管理员生成短期、一次性、绑定访客来源的随机迁移票据，私下写入该设备的加密待迁移存储。用户登录后页面说明迁移到哪个账号，并确认。未来其他旧设备缺少证明时重新授权平台，不提供不安全的自动认领。

票据服务端只保存哈希、来源、有效期与已消费状态；领取在同一事务核对当前账号、锁定票据、读取来源凭证，解密后以目标账号 AAD 重新加密。目标平台已有凭证时保留目标，返回冲突状态供用户选择重新授权，不覆盖；成功后撤销来源可用性并更新/移除导出 Cookie 文件。重复领取不再次转移。票据、Cookie、密码均不进入源码/聊天/诊断。

## 部署、备份与回滚

1. 在隔离数据库完成迁移/鉴权/越权/并发测试，Android 构建完成。审查 Nginx 精确路径，确保没有意外开放 legacy 路由。
2. 通过 SQLite backup 保存 tx 一致快照，备份原 Nginx 配置及记录当前代码版本；保留音频与密钥，不输出凭据。
3. 部署 API 与数据库迁移，旧 Basic 入口仍有效；验证新增路由的无令牌拒绝以及两账号隔离。
4. nginx -t 通过后 reload，只开放新账号入口。公网验证无需 Basic 的注册/登录、令牌访问与越权拒绝；不开放 8800。
5. 使用原包/原签名升级手机，验证真实账号服务器提取与下载，保持本地音频。
6. 数据迁移失败不修改 Nginx；应用验收失败可先回退 Nginx 入口，保留旧 Basic 访问。完整数据库回滚需暂停写入，恢复同一快照与兼容代码，明确备份后新写入数据处理，不能直接覆盖运行库。

部署本身属于本次功能恢复范围；系统权限或自动审核若另有拒绝，再据实际拒绝原因处理。不得将部署计划写成已部署。

## 必须验证

- 无 Basic 注册/登录；无令牌、过期、退出后的令牌均不能提取/同步/下载/读取授权。
- 两个隔离账号互查曲目、下载 ID、二维码、凭证、助手候选与回执全部拒绝；伪造 user_id 无效。
- 同账号重复提取去重；跨账号同链接独立验证平台访问；force、并发及临时文件不能覆盖另一账号。
- 迁移票据过期、重放、错误来源、目标已有授权、事务失败全部不会转移/丢失凭证。
- 旧数据库迁移保持 ID、文件、任务及播放列表引用；旧 Basic 入口仍受保护。
- 手机本地提取、播放、批量删除、两账号切换及晚到同步结果；各账号游标不互相复用。
- 真机真实注册/登录、公开链接服务器提取→下载→播放；平台真实授权受平台状态影响时单独记录，模拟测试不得称为平台真实成功。
- 编译/JVM/Python 回归及真实公网验证通过后，再更新 README、技术文档，推送 GitHub，追加 GetAudio 账号主题飞书文档，标注实际提交及已验证边界。
